# Known limitations

- `MEDLENS_SPEC.md` is not present in this checkout. The seven catalog categories were selected in the importer manifest because the spec's category list was unavailable here.
- The installed catalog is 40 single-ingredient medicines with explicit U.S. FDA OTC label classification. It is not an Indian market or regulatory classification. U.S. labels may not match Indian product labels or local guidance; Indian brand names are deliberately unavailable unless a verifying source is added.
- Label content is taken from the FDA label fields and cleaned conservatively by dropping dosage/duration-bearing sentences and directions headings. This can omit useful safety context, and automated text filtering cannot guarantee every possible dosage phrasing is removed. Have a pharmacist review the dataset before using it for care decisions.
- Online OpenFDA lookups are user initiated from Explore, exact generic-name only, and reject combination/unknown product classes. The feature is not tested on every network or FDA record shape. Cached catalog entries are shared locally on the device, not personalized by account.
- The app and importer have no RxNorm enrichment; the synonym map is maintained in the checked-in JSON files and can be expanded.
- The AI serverless proxy is implemented but not deployed or live-tested against a Gemini project. Set the Vercel provider key and GitHub Actions `MEDLENS_BACKEND_URL` before expecting online responses. A real API key is never stored in the project. The in-memory backend rate limit is per serverless process rather than global across all Vercel instances.
- Backend unit tests and type-checks do not call Gemini. Online replies are protected by prompt instructions and response validation but still require ongoing review and should not be relied on for medical decisions.
- Voice input uses the Android speech-recognition service and its privacy terms. Local Room data, including chats, is not encrypted at rest; local accounts do not sync and have no password recovery.
- Latest local verification completed `lintDebug`, `testDebugUnitTest`, `assembleDebug`, and minified `assembleRelease` successfully. The 18 Android unit tests pass. Full debug lint reports 0 errors and 11 warnings, primarily old-but-working target/dependency version notices. The release output from the latest unsigned verification is `app-release-unsigned.apk`; a user-installable signed release requires the documented keystore secrets. R8 9.4.14 emits two class-file-provider async-parsing warnings and packages two native libraries without stripping them.
- No Android device or emulator is available here. Rotation, process-death restoration, airplane-mode interruption, slow network behavior, install, visual clipping, and tap-through behavior still need a physical-device check. Backend status/timeout fallback behavior has unit-level tests; no live production backend request was made.
- The signed release workflow requires the four documented GitHub Actions keystore secrets. They are not configured in this local checkout, so GitHub must be configured before it can produce a user-installable signed release APK.
- This checkout has no `.git` metadata, so changes could not be committed or pushed. Upload or push the project root `C:\Users\admin\Desktop\rug_project` (including `.github/`) to the GitHub repository to trigger Actions.
